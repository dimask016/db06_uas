Catatan implementasi: Setiap tabel mencerminkan struktur SQL asli. Driver independen (tidak terhubung ke User login). Batch tidak sebagai tabel terpisah, tapi kolom batch_number di goodsreceiptdetail. Relasi N:M dipecah menggunakan junction table (contoh: inventory menghubungkan product & location).
🔁 Alur Transfer + Driver + Shipment:
• TransferRequest (permintaan) → Transfer (header) → TransferDetail (per produk).
• Shipment menghubungkan transfer_id, vehicle_id, driver_id.
• Driver adalah data pengemudi (lisensi, status) tanpa relasi langsung ke User sistem.

📚 Konsep Lanjutan Database (diterapkan)

🧩 Weak Entity (Entitas Lemah)

Entitas yang tidak memiliki primary key sendiri dan bergantung pada entitas induk (owner). Diimplementasi dengan ON DELETE CASCADE.

✓ Diterapkan pada tabel:

  • TransferDetail → bergantung pada TransferHeader (foreign key transfer_id)
  • PurchaseOrderDetail → bergantung pada PurchaseOrder
  • GoodsReceiptDetail → bergantung pada GoodsReceipt

🌳 Generalization / Specialization

Location (Superclass) → warehouse dan site (atribut location_type ENUM).
Jenis: Disjoint Partial Specialization (sebuah location hanya bisa warehouse ATAU site).

⚙️ Participation (Total / Partial)

  • Total Participation → Setiap Product harus memiliki record di Inventory (wajib terdaftar di minimal satu lokasi).
  • Partial Participation → Tidak semua User harus menjadi TimLogistik.
