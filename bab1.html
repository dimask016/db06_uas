1.1 Latar Belakang

Saat ini, banyak perusahaan membutuhkan sistem yang rapi untuk mengatur distribusi barang, terutama antara gudang (warehouse) dan lokasi operasional atau cabang (site). Namun, pada kenyataannya masih banyak perusahaan yang mengelola data pengiriman dan permintaan barang secara manual, seperti menggunakan Microsoft Excel atau bahkan melalui chat seperti WhatsApp.

Cara tersebut sering menimbulkan masalah, seperti data tidak sinkron, kesalahan pencatatan, dan sulitnya melacak riwayat pengiriman barang. Selain itu, permintaan barang dari site ke warehouse sering tidak tercatat dengan baik, sehingga bisa menyebabkan keterlambatan atau kesalahan pengiriman.

Solusi yang diusulkan: Sistem berbasis database untuk mencatat dan mengelola proses distribusi barang, mengatur proses pengiriman dari warehouse ke site (transfer) serta permintaan barang dari site ke warehouse (transfer request) agar lebih rapi, jelas, dan mudah dipantau.
1.2 Rumusan Masalah
  • Bagaimana cara mencatat pengiriman barang dari warehouse ke site dengan lebih rapi?
  • Bagaimana cara mengelola permintaan barang dari site agar tidak tercecer atau hilang?
  • Bagaimana menghubungkan data produk, warehouse, dan site dalam satu sistem?
  • Bagaimana menyediakan informasi distribusi barang yang jelas dan mudah dipahami?
1.3 Tujuan
  • Membuat sistem database untuk mencatat pengiriman barang (transfer).
  • Membuat fitur untuk mencatat permintaan barang dari site (transfer request).
  • Menghubungkan data produk, warehouse, dan site dalam satu sistem.
  • Membantu proses distribusi barang menjadi lebih cepat dan teratur.
  • Menyediakan data yang bisa digunakan untuk monitoring.
1.4 Manfaat

Bagi Perusahaan

  • Mempermudah pengelolaan distribusi barang
  • Mengurangi kesalahan pencatatan manual
  • Data lebih rapi dan terpusat

Bagi Pengguna

  • Staff warehouse lebih mudah mencatat pengiriman
  • Admin site lebih mudah melakukan request barang
  • Manager bisa memantau data dengan lebih jelas

Bagi Pengembangan Sistem

  • Bisa dikembangkan menjadi sistem yang lebih besar
  • Bisa dijadikan dasar untuk aplikasi berbasis web
1.5 Batasan Masalah

Agar pembahasan tidak terlalu luas, sistem ini dibatasi pada:

  • Hanya membahas distribusi barang antara warehouse dan site.
  • Data yang digunakan meliputi:
    Produk Warehouse Site Transfer Transfer request
  • Tidak membahas pembayaran atau keuangan.
  • Fokus pada pembuatan database dan query SQL.
  • Tidak membahas tampilan aplikasi (frontend murni).
1.6 Target User

Staff Warehouse

Bertugas untuk:

  • Mengelola pengiriman barang ke site
  • Mencatat data transfer barang
  • Melihat dan memproses permintaan barang dari site
Pengguna utama

Admin Site (Cabang)

  • Mengajukan permintaan barang ke warehouse (transfer request)
  • Melihat status permintaan (disetujui, ditolak, proses)
Koordinator lapangan

Manager / Supervisor Operasional

  • Memantau proses distribusi barang
  • Melihat laporan pengiriman dan permintaan
  • Mengambil keputusan terkait stok dan distribusi
Monitoring & Analisis

Tidak selalu input data, fokus pada insight

Keterlibatan langsung: Staff warehouse & Admin site sebagai penggerak utama, Manager sebagai pengambil keputusan strategis.
